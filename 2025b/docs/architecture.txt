1. ТЕКУЩЕЕ УСТРОЙСТВО

Рабочие файлы разделены по ответственности:
- run.m: графический ввод параметров, проверка ввода, запуск.
- mesh/: readAreaMatrix.m, validateMeshGeometry.m, savedMesh.m — импорт и библиотека геометрий.
- mesh/saved_mesh/: именованные MAT с двумя матрицами, отдельно для каждой версии.
- main.m: параметры, инициализация состояния, первый расчёт и основной цикл.
- model/: физическая модель и обновление состояния.
- solver/: численное решение и checkSteadyState.m — наблюдение стационарности.
- visualization/: drawNetwork.m, plotNetwork.m и writeSaturationPressureGif.m.
- reporting/: замер времени, запись выбранных MAT, выборка и отдельная сборка PDF.
- results/: отдельная папка автоматического запуска с MAT; PDF по выбору.
- tests/: проверка MAT после расчёта; отчёты tests_relults.txt рядом со снимками.
- setupProject.m: подключение рабочих папок.

Основная структура данных — Net. Большинство расчётных функций получает
Net и возвращает обновлённый Net. Разделение вычислений на функции уже есть;
глубокая иерархия папок для такого количества файлов не нужна.

3. СВЯЗИ

run -> results/last_settings/run-settings.mat своей версии (inputs и previousGeometry): хранение полей
окна и точных матриц площадей последней запущенной сети. «Сохранить» и «Сохранить и запустить» записывают временный MAT,
затем заменяют файл. Обычное закрытие не перезаписывает сохранённое.
При открытии файл имеет приоритет над прежним appdata-кешем; при отсутствии
обоих действуют исходные дефолты. Данные переживают перезапуск MATLAB.
Геометрия сети: предыдущая (Ah/Av из настроек, без rand), новая (ручной ввод,
случайная или загрузка двух Excel/.m) либо выбранная из mesh/saved_mesh активной версии.
run -> readAreaMatrix -> validateMeshGeometry: импорт без исполнения .m-файлов.
run -> mesh/savedMesh -> mesh/saved_mesh/<название>.mat: именованные Ah/Av, м².
«Сохранить сеть» не запускает расчёт и не меняет previousGeometry: сохраняет
геометрию отдельно и переключает окно на эту запись. Случайная сеть не генерируется
повторно при запуске сохранённой записи. Повторное имя требует подтверждения замены.
«Сохранить» сохраняет только ввод и прежнюю previousGeometry; «Сохранить и запустить»
записывает фактические Ah/Av с вводом перед main. Пустой список/невалидный файл
блокируют запуск с сообщением. Пути импорта и выбор записи хранятся в inputs.
Библиотеки 2025b/2023a раздельные, формат MAT общий; пользовательские MAT можно
копировать между версиями. saved_mesh не подключается в path.
Новых полей Net нет; прежний блок Net.H.A=Ah, Net.V.A=Av и передача в main сохранены.
VerticalBC больше не вводится в run: окно задаёт false, старые значения файла
игнорируются. main и функции модели/решателя этой правкой не менялись.
Сетки uigridlayout задают раскрывающиеся группы «Физические параметры»,
«Параметры сети» и «Результаты» (периодичность MAT и GIF). Кнопки сохранения находятся вне прокрутки; предпросмотр — в группе сети.
main при прямом запуске использует собственные параметры и не читает файл окна.
run -> plotNetwork (предпросмотр)
run -> resetSimulationWorkspace(true) -> очистка base workspace и старых окон.
run -> runParameters/runModelOptions/runRecordResults -> main (через assignin/evalin).
runModelOptions несёт выбор includeAadd и meniscusModel отдельно от Net.
main задаёт значения для прямого запуска (true и 2), читает выбор из окна
и удаляет одноразовую структуру. Только main задаёт коэффициенты:
includeAadd=false -> xi=0; meniscusModel=1 -> coef=0 и P_crit_width=0.
При meniscusModel=2 сохраняются положительные coef и ширина перехода.
В окне по умолчанию выбраны два режима и включена A_add.
Новых полей Net нет; основной цикл и порядок расчётных вызовов сохранены.
main -> resetSimulationWorkspace -> свежий Net из runParameters либо параметры
по умолчанию; старые переменные, окна и persistent-сессия отчёта удаляются.
Только «Сохранить и запустить» передаёт runRecordResults=true: автоматический
расчёт с записью выбранных MAT. main применяет и удаляет этот переключатель.
«Сохранить» записывает только ввод окна и оставляет его открытым.
PDF автоматически не формируется; группа «Результаты» задаёт периодичность MAT и создание GIF после расчёта.
main проверяет диапазон диаметров непосредственно в скрипте
(однократно до расчёта; warning вне 0.1–1 мм, отдельного helper нет).
main -> solvePressureFlow -> pressureFlowScaling
                         -> calcResidualJacobian -> capillaryEquation
main -> checkSteadyState (до следующего шага; наблюдение и флаги вне Net)
main -> calcCanMove -> calcWaterConnectivity
main -> calcTimeStep
  calcTimeStep читает текущие узловые/граничные давления и Dir: минимум
  аналитических вязких оценок до заполнения во всех режимах, без Q/Regime.
  calcSaturation по-прежнему продвигает мениски линейно по фактическому Q.
  Поэтому dt — оценочный шаг, а не гарантированное время первого заполнения.
main -> calcSaturation -> calcState
main -> simulationReport -> saveSimulationStep -> MAT (снимки)
                        -> measureComputeTime (только таймер)
                        -> questdlg / drawNetwork (пошаговый режим)
showSimulationReportDialog -> writeSimulationReport
                                 -> selectSimulationReportSteps (выборка)
writeSimulationReport -> loadSimulationStep -> drawNetwork (PDF)
Пошаговый режим остаётся доступным при прямом main без флага.
tests/runTests -> checkResults -> чтение MAT -> tests_relults.txt в папке запуска.
Проверка запускается отдельно после расчёта; внутрь main не встроена.
Она не вызывает функции обновления модели и не меняет сохранённый Net.

Первый расчёт в main:
solvePressureFlow -> calcTimeStep -> simulationReport.

Один шаг цикла после сохранения предыдущего состояния:
calcSaturation -> calcState -> calcCanMove -> solvePressureFlow -> calcTimeStep
-> simulationReport('snapshot').
Порядок восстановлен из 86f8807 по отдельному согласованию 21.09.2026;
30.09.2026 удалены предварительный выбор режима и снимок перед решением.
компактная структура main и текущие параметры пользователя сохранены.
В режиме записи вместо экранной отрисовки
сохраняется снимок MAT. После завершения сохраняется summary.mat без PDF.
PDF формируется отдельно по сохранённым состояниям; выборка не влияет на расчёт.

4. ЧТО ВАЖНЕЕ ПЕРЕНОСА ПО ПАПКАМ

А. Передача параметров run -> main выполняется через одноразовый runParameters;
прежний Net при каждом запуске main очищается.
При отсутствии Net.V.P0 задаётся 200 Па. В интерфейсе отдельного поля для
верхнего давления пока нет. Вынос цикла отменён 18.09.2026: первый расчёт
и основной цикл восстановлены непосредственно в main; simulateNetwork удалён.
21.09.2026 компактная структура main восстановлена по e1edfa. Затем по
отдельному поручению порядок вызовов возвращён из 86f8807, без переноса цикла. Подготовка записи, замеры, снимки и PDF обслуживаются через
вызовы simulationReport; последовательность обновления модели задаётся в main. Перенос основных блоков без отдельного
согласования запрещён в AGENTS.md.
Присваивания k/coef/xi/P_crit_width находятся после приёма свежего Net;
исправлено подавление параметров по умолчанию при запуске после clear Net.
Повторный прямой main начинает с параметров своего блока инициализации.
Существующий Net не используется; геометрия и жидкости окна передаются через
runParameters, выбор модели — отдельно через runModelOptions; оба входа одноразовые.

Г. Имя run совпадает с именем стандартной функции MATLAB.
При согласованной переработке интерфейс лучше назвать runCapillaryApp.

Д. Отдельного поля статуса решателя нет. С 29.09.2026 solvePressureFlow
при превышении допуска после итераций вызывает NoConvergence и не возвращает
непринятое решение. Прежнее возвращение результата с warning исправлено.
С 20.10.2026 прорыв запускает наблюдение checkSteadyState; main сообщает о нём
один раз и продолжает расчёт до стабильности Sat/State/Dir/Move и затем P.
Проверка не меняет Net; данные stationarity сохраняются отдельно в summary.
При Inf dt без движущихся менисков основной цикл выполняет подтверждение
без продвижения времени: calcSaturation ничего не меняет; calcState проверяет
отложенное появление менисков, затем решатель подтверждает давление.
Остальные условия остановки: плохой dt, лимит шагов, ручной стоп или ошибка.
При ошибке try/catch в main вызывает
simulationReport('fail',...), восстанавливает последний принятый Net и повторно
выбрасывает исходное исключение. Helper записывает причину, время неудачного
вычисления в summary.mat без автоматического PDF. Пошаговый режим сохраняет диалоги.

Е. Формулы Pc, Aeff и B, а также выбор соседних узлов повторяются.
При развитии модели полезно выделить общие вычисления и соглашения об
индексации. Сейчас сами папки не устранят это дублирование.

Ж. Комментарий к VerticalBC=false исправлен: границы закрыты.

З. Новая физика согласована 08.10.2026. Для одного мениска dp — приложенный
перепад без вычитания статического давления. Плато: v=(dp/B)^3;
вязкая ветвь: v=dp/(A_class+A_add), A_add=xi*(mu1+mu2)/r.
Центр перехода P_crit=coef*r^(-5/4), полная ширина по умолчанию P_crit_width=4 Па.
С 20.10.2026 main допускает вязкий вариант: coef=width=0. При dp>0
существующая формула сразу выбирает вязкую ветвь без сглаживания/деления на 0.
xi=0 независимо отключает дополнительное сопротивление в расходе и dt.
Решатель и checkResults принимают нулевые coef/width/xi, k остаётся >0.
Квинтический вес соединяет ветви с точной производной для Ньютона.
Regime=1/3 — диагностические стороны центра; третьего физического режима нет.
Старые отрицательная поправка, граница пересечения и case 2 удалены из модели.
Один solvePressureFlow на шаг совместно решает балансы и расходные уравнения;
storeSolvedBranches записывает Move/Regime по принятому P. Move=2 сохраняет
защемление; Move=1 при dp>0, Move=3 при dp<=0. Порядок main не менялся.
Новые MAT имеют flowLaw=smoothMeniscusAppliedPressure. checkResults независимо
проверяет их формулу; архивные MAT сохраняют прежние правила. В PDF выводятся
новые константы, P_crit и dp-P_crit (положение относительно смены режима).
Ограничение: при малых радиусах закон может иметь отрицательную производную.
Она не скрыта и не обрезана; гладкость не гарантирует глобальную сходимость
или единственность решения такой сети. Требуется уточнение физики для этих условий.
