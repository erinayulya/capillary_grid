ЗАПУСК ПРОЕКТА

В MATLAB перейти в корень capillary_grid.

  run                 окно параметров (сохраняется прежнее имя)
  main                интерактивный расчёт с текущей логикой main

В run геометрия задаётся двумя способами: «Матрица площадей» (по умолчанию)
и «Случайная». При открытии окна сразу видны поля матриц H.A и V.A.
Окно автоматически уменьшается под экран и центрируется на мониторе
с указателем мыши; размер шрифтов и элементов уменьшается пропорционально.

Обе точки запуска сами вызывают setupProject. Для отдельных функций:

  setupProject
  % Затем solvePressureFlow(Net), drawNetwork(Net) и т. д.

При работе из другой папки сначала подключить корень:
  addpath('C:/Users/erina/Documents/MATLAB/Disser/capillary_grid')
  setupProject

setupProject меняет path только текущего сеанса и не сохраняет его глобально.
Не использовать addpath(genpath(...)): подключайте только рабочие папки через
setupProject.

РЕЖИМ «ПОСЧИТАТЬ И ЗАПИСАТЬ РЕЗУЛЬТАТЫ»

В run выбрать «Запустить по шагам» для интерактивного режима или
«Запустить и сохранить результаты» для автоматического расчёта с PDF/MAT.
Кнопка «Нарисовать» сохраняет предпросмотр геометрии.
При прямом запуске main без флага используется пошаговый режим.
Для записи: runRecordResults = true; main. Флаг действует только на один запуск.
false сохраняет интерактивный режим с рисунками и кнопкой «Продолжить».
true рассчитывает автоматически, без окон графиков и вопросов о продолжении.
Параметры, заданные в run, сохраняются при переходе в main.
Каждый прямой main автоматически очищает предыдущие переменные и начинает
с параметров своего блока инициализации. Старый Net не используется.
При открытии run также очищаются прежние переменные и окна; введённые в окне
параметры передаются в main однократно. Оба запуска закрывают прежние окна
графиков и сбрасывают сессию отчёта. Папки results на диске не удаляются.
После завершения нового расчёта его переменные и новые графики остаются доступны.

Каждый запуск создаёт отдельную папку results/run_<дата>_<уникальный суффикс>/:
- report.pdf: титульный лист, начальное состояние (шаг 0), листы шагов;
- parameters.mat: Net перед первым вызовом решателя;
- step_000000.mat и последующие: Net (как на странице PDF), solvedNet (после решения),
  reportPhase, flowLaw, step, dtUsed, elapsedTime, stepComputeTime, totalComputeTime;
- summary.mat: result, parameters и последнее принятое Net.

dtUsed - интервал выполненного шага; solvedNet.dt - интервал следующего шага.
С 30.09.2026 на всех шагах Net=solvedNet: P/Q/Move/Regime относятся к одному
принятому решению. reportPhase='afterSolve'. summary.Net — итог решения.
Архивные MAT со снимком до решения сохраняют прежнее содержание при чтении.
Старые MAT с reportNet читаются функцией loadSimulationStep без изменения файла.
На шаге 0 dtUsed=0, elapsedTime=0. Общее время равно сумме dtUsed,
не включает ещё не выполненный следующий шаг и время работы компьютера.
В PDF приведены P и обе ориентации Q, Dir, Sat, State, Move, Regime.
Верхние и левые ячейки индексов таблиц выделены одинаковым цветом.
Большие сети получают увеличенный формат листа, чтобы не обрезать таблицы.
Для просмотра чисел полной точности использовать MAT-файлы.

При отсутствии конечного положительного dt или достижении 10000 шагов
автоматический расчёт завершается с объяснением на титульном листе.
При перехваченной ошибке сохраняются завершённые MAT, причина ошибки, время
неудачного вычисления и частичный PDF; затем MATLAB повторно показывает
исходную ошибку. Net восстанавливается к последнему принятому состоянию.
При принудительном прерывании без catch итоговый PDF может отсутствовать.

Повторная сборка отчёта: setupProject; writeSimulationReport('путь к папке запуска').
Известные ограничения решателя перечислены в architecture.txt.

Хронометраж (18.09.2026): stepComputeTime — время вычислений данного шага,
totalComputeTime — накопленное время вычислений, включая шаг 0 (секунды).
В summary.mat result.totalComputeTime включает завершённые снимки и
result.failedComputeTime — время неудачного вычисления при перехваченной ошибке. Запись MAT, создание PDF, графики, диалоги
и инициализация main в замер не входят. PDF показывает итог на первом листе,
время шага и накопленное время — на каждом листе состояния.
Для старых MAT без хронометража PDF выводит «не измерялось».

ПРОВЕРКА СОГЛАСОВАННОСТИ СОХРАНЁННЫХ РАСЧЁТОВ (18.09.2026)

Перейти в папку tests рядом с results и выполнить:
  runTests

Будут проверены снимки step_*.mat во всех папках запусков results.
В каждой папке создаётся/перезаписывается tests_relults.txt (имя сохранено
по запросу пользователя). Исходные MAT, PDF и код расчётной модели не меняются.
testSummary в workspace содержит сводку по папкам. Для одной папки:
  report = checkResults(fullfile('..','results','run_20260916_095548_tp06ffb17a_68a5_4738_83fe_865a7d8e5f28'));
Без аргументов checkResults также проверяет results этого проекта.
Функции tests не требуют подключения папок модели: работают независимо,
не вызывают genpath и не запускают новый расчёт.

В отчёте: полный путь MAT, правило, индекс капилляра/узла, значения и причина.
Только при отсутствии ошибок и предупреждений итоговая строка — all correct.
ERROR: нарушение состояния, баланса, перехода, причины завершения либо данные,
без которых часть проверки невозможна. WARNING: дополнительное требование,
которое текущая модель не гарантирует. Предупреждения не скрываются.

Уточнения правил:
1. Первая фаза — State=0; State=1 — мениск; вторая фаза — State=2.
2. P сравнивается с диапазоном граничных давлений: 0, H.P0 и V.P0, если
   вертикальные границы открыты. Границы сортируются, поэтому отрицательный P0
   допустим. Выход P за диапазон отмечается WARNING: при капиллярных перепадах
   или изолированных узлах это не универсальный закон для текущей модели.
3. Допуск баланса и нулевого Q — 1e-19 м³/с по Newton tol*qScale;
   давление сравнивается с допуском 1e-5 Па, Sat — 1e-12.
   Допуск давления не означает доказанную погрешность P. Настройки доступны:
     report = checkResults('путь к папке', struct('flow',1e-18,'pressure',1e-5));
4. sign(Q) сравнивается с Dir только у менисков и вне допуска нулевого расхода.
   Для State=0/2 требуется Dir=0, но Q может быть ненулевым.
5. Move=3 требует dP=Dir*DeltaP<=Pc, включая равенство, и нулевой расход.
   Pc=2*sigma*cos(theta)/sqrt(A/pi). Удержание по новому P проверяется отдельно
   от выбора Move по прежнему P: первый случай — WARNING, неправильный выбор
   по прежнему P — ERROR. При окончательной остановке неверный порог — ERROR.
6. Regime=0 у неподвижного мениска — требование пользователя; текущая функция
   сохраняет старый режим. Это WARNING. Для Move=1 нужны Regime=1/2/3 и |Q|>допуска.
7. Move=2 требует Q=0 и сохранения защемления. Причина — потеря пути отвода
   воды/закрытая граница/историческое защемление; dP<=Pc для него не обязательно.
8. Между соседними шагами ожидаемое продвижение восстанавливается по прежним
   Q и dtUsed. Мениск либо остаётся с прежним Dir и ожидаемой Sat, либо
   достигает Sat>=1-1e-12 и превращается в State=2. Новые мениски с Sat=0
   допустимы только на выходящих из достигнутого узла рёбрах по прежнему Q.
   Проверяются лишние и отсутствующие мениски, *_prev и неизменность параметров.
9. Причина завершения сверяется с summary.mat: прорыв, отсутствие конечного dt,
   лимит, остановка пользователем либо ошибка. Лимит/ручная остановка не требуют
   неподвижности всех менисков. Для остановки по dt отдельно разбирается каждый
   мениск. Неизвестная причина/отсутствующий summary не выдаёт all correct.

Полные капиллярные уравнения и выбор конкретной ветви Regime по Pi этот набор
правил не проверяет. all correct относится к перечисленным проверкам.
Для контрольных примеров самого валидатора выполнить из tests:
  testCheckResults
Они сохраняются в отдельной автоматически созданной папке tmp/ проекта.
