1. ТЕКУЩЕЕ УСТРОЙСТВО

Рабочие файлы разделены по ответственности:
- run.m: графический ввод параметров, проверка ввода, запуск.
- main.m: параметры, инициализация состояния, первый расчёт и основной цикл.
- model/: физическая модель и обновление состояния.
- solver/: 3 файла численного решения.
- visualization/: drawNetwork.m и plotNetwork.m для отрисовки.
- reporting/: замер времени, запись снимков MAT и создание PDF; без основного цикла.
- results/: отдельная папка каждого запуска с PDF и MAT.
- tests/: проверка MAT после расчёта; отчёты tests_relults.txt рядом со снимками.
- setupProject.m: подключение рабочих папок.

Основная структура данных — Net. Большинство расчётных функций получает
Net и возвращает обновлённый Net. Разделение вычислений на функции уже есть;
глубокая иерархия папок для такого количества файлов не нужна.

собственного файла. main и run вызывают его автоматически. Для прямого
вызова отдельных функций сначала выполнить setupProject из корня проекта.
3. СВЯЗИ

run -> plotNetwork (предпросмотр)
run -> resetSimulationWorkspace(true) -> очистка base workspace и старых окон.
run -> runParameters/runRecordResults -> main (через assignin/evalin).
main -> resetSimulationWorkspace -> свежий Net из runParameters либо параметры
по умолчанию; старые переменные, окна и persistent-сессия отчёта удаляются.
Кнопки run передают одноразовый runRecordResults: пошаговый режим false,
сохранение PDF/MAT true. main применяет и удаляет этот переключатель.
main -> solvePressureFlow -> pressureFlowScaling
                         -> calcResidualJacobian -> capillaryEquation
main -> calcCanMove -> calcWaterConnectivity
main -> calcRegime
main -> calcTimeStep
main -> calcSaturation -> calcState
main -> simulationReport -> saveSimulationStep -> MAT (снимки)
                        -> writeSimulationReport -> drawNetwork (PDF)
                        -> measureComputeTime (только таймер)
                        -> questdlg / drawNetwork (пошаговый режим)
tests/runTests -> checkResults -> чтение MAT -> tests_relults.txt в папке запуска.
Проверка запускается отдельно после расчёта; внутрь main не встроена.
Она не вызывает функции обновления модели и не меняет сохранённый Net.

Первый расчёт в main:
solvePressureFlow -> calcTimeStep -> simulationReport.

Один шаг цикла после сохранения предыдущего состояния:
calcSaturation -> calcState -> calcCanMove -> calcRegime
-> simulationReport('capture') -> solvePressureFlow -> calcTimeStep
-> simulationReport('snapshot').
Порядок восстановлен из 86f8807 по отдельному согласованию 21.09.2026;
компактная структура main и текущие параметры пользователя сохранены.
В режиме записи вместо экранной отрисовки
сохраняется снимок MAT. После завершения собирается PDF с итогом на первом листе.

4. ЧТО ВАЖНЕЕ ПЕРЕНОСА ПО ПАПКАМ

А. Передача параметров run -> main выполняется через одноразовый runParameters;
прежний Net при каждом запуске main очищается.
При отсутствии Net.V.P0 задаётся 200 Па. В интерфейсе отдельного поля для
верхнего давления пока нет. Вынос цикла отменён 18.09.2026: первый расчёт
и основной цикл восстановлены непосредственно в main; simulateNetwork удалён.
21.09.2026 компактная структура main восстановлена по e1edfa. Затем по
отдельному поручению порядок вызовов возвращён из 86f8807, без переноса цикла. Подготовка записи, замеры, снимки и PDF обслуживаются через
шесть штатных вызовов simulationReport (включая capture); функции модели вызываются только из main. Перенос основных блоков без отдельного
согласования запрещён в AGENTS.md.
Присваивания kdyn/bound возвращены после проверки существования Net;
исправлено подавление параметров по умолчанию при запуске после clear Net.
Повторный прямой main начинает с параметров своего блока инициализации.
Существующий Net не используется; параметры окна передаются только через runParameters.

Г. Имя run совпадает с именем стандартной функции MATLAB.
При согласованной переработке интерфейс лучше назвать runCapillaryApp.

Д. Нет явного успешного/неуспешного статуса решателя.
solvePressureFlow при превышении допуска после итераций предупреждает,
но возвращает результат. Это ограничение самого решателя сохраняется.
Автоматический режим останавливается при неконечном/неположительном dt,
прорыве или достижении лимита шагов. При ошибке try/catch в main вызывает
simulationReport('fail',...), восстанавливает последний принятый Net и повторно
выбрасывает исходное исключение. Helper записывает причину, время неудачного
вычисления и частичный PDF. Пошаговый режим сохраняет диалоги.

Е. Формулы Pc, Aeff и B, а также выбор соседних узлов повторяются.
При развитии модели полезно выделить общие вычисления и соглашения об
индексации. Сейчас сами папки не устранят это дублирование.

Ж. Комментарий к VerticalBC=false исправлен: границы закрыты.

З. Проверка результатов добавлена 18.09.2026. Она обнаруживает расход против
Dir у менисков в существующих MAT. calcSaturation при этом использует abs(Q).
В результатах до восстановления e1edfa Move/Regime выбирались по прежнему P
и после решения не уточнялись; встречается
Move=3 при новом dP>Pc, в том числе при остановке без прорыва. У неподвижных
менисков calcRegime сохраняет прежний код. Проверка выдаёт эти несоответствия,
но формулы модели не исправлены. Текущий порядок вновь обновляет Move и Regime
перед решением, как в 86f8807. Ошибка отката — изменение Move/Regime после
solvePressureFlow с сохранением прежних Q — исправлена возвратом порядка.
Это не доказывает устранения остальных перечисленных проблем модели.
