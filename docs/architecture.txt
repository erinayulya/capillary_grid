1. ТЕКУЩЕЕ УСТРОЙСТВО

Рабочие файлы разделены по ответственности:
- run.m: графический ввод параметров, проверка ввода, запуск.
- main.m: начальные данные, инициализация состояния, цикл, диалоги.
- model/: 7 файлов физической модели и обновления состояния.
- solver/: 3 файла численного решения.
- visualization/: drawNetwork.m и plotNetwork.m для отрисовки.
- setupProject.m: подключение рабочих папок.

Основная структура данных — Net. Большинство расчётных функций получает
Net и возвращает обновлённый Net. Разделение вычислений на функции уже есть;
глубокая иерархия папок для такого количества файлов не нужна.

analysis/ содержит диагностику, журналы и source_snapshot/ — снимок старого
кода. Это отдельный исторический материал, а не второй рабочий решатель.
benchmark_scaling, benchmark_detail, diagnose_move добавляют source_snapshot
в начало path и восстанавливают path через onCleanup. Фактический выбор
функции также зависит от текущего каталога MATLAB: его приоритет выше path.
Перед сравнением версий проверять which solvePressureFlow -all.
Не добавлять весь проект через addpath(genpath(...)): это включит снимок.

Это один уровень вложенности по ответственности. Локальные функции
calcOneRegime, processNode и подобные разумно оставить в их .m-файлах:
они обслуживают конкретную основную функцию.

setupProject подключает корень, model, solver и visualization относительно
собственного файла. main и run вызывают его автоматически. Для прямого
вызова отдельных функций сначала выполнить setupProject из корня проекта.
analysis подключается отдельно; source_snapshot не входит в рабочий путь.

3. СВЯЗИ

run -> plotNetwork (предпросмотр)
run -> main (через assignin/evalin и базовое рабочее пространство)
main -> solvePressureFlow -> pressureFlowScaling
                         -> calcResidualJacobian -> capillaryEquation
main -> calcCanMove -> calcWaterConnectivity
main -> calcRegime
main -> calcTimeStep
main -> calcSaturation -> calcState
main -> drawNetwork

Первый расчёт в текущем main:
solvePressureFlow -> calcTimeStep -> drawNetwork.

Один шаг цикла после сохранения предыдущего состояния:
calcSaturation -> calcState -> calcCanMove -> calcRegime
-> solvePressureFlow -> calcTimeStep -> drawNetwork.
Это актуальный пользовательский порядок вызовов; перенос папок его не менял.

4. ЧТО ВАЖНЕЕ ПЕРЕНОСА ПО ПАПКАМ

А. Передача параметров интерфейса нарушена.
run/startMain записывает Net в base workspace, затем вызывает main.
Первая строка main — clear all; Net удаляется, и main создаёт значения
по умолчанию. Желательное решение: явная функция расчёта с аргументом Net.
Это замечание по исходникам; исправление не выполнено.

Б. В run/startMain не задаётся Net.V.P0.
После устранения очистки Net это потребуется учесть для открытых верхней
и нижней границ. Сейчас очистка маскирует неполноту параметров интерфейса.

В. main объединяет конфигурацию, инициализацию, расчёт и взаимодействие
с пользователем. Для пакетных экспериментов полезно позднее выделить
создание начального Net и один расчётный шаг в отдельные функции.

Г. Имя run совпадает с именем стандартной функции MATLAB.
При согласованной переработке интерфейс лучше назвать runCapillaryApp.

Д. Нет явного успешного/неуспешного статуса решателя.
solvePressureFlow при превышении допуска после итераций предупреждает,
но возвращает результат. main не останавливает расчёт при dt = Inf.
Эти условия стоит явно обработать в последующей правке логики.

Е. Формулы Pc, Aeff и B, а также выбор соседних узлов повторяются.
При развитии модели полезно выделить общие вычисления и соглашения об
индексации. Сейчас сами папки не устранят это дублирование.

Ж. В main комментарий к VerticalBC=false говорит о проницаемых границах;
по расчётному коду false означает закрытые границы. Справочник переменных
описывает фактическую логику, а не этот комментарий.

5. ГРАНИЦЫ АНАЛИЗА

При переносе проверены хеши всех 12 перемещённых файлов: содержимое сохранено.
В отдельном процессе MATLAB R2025b проверены пути из другого текущего каталога,
однофазная сеть 2x2 (давления 1000/500 Па при входных 1500 Па, ожидаемые
горизонтальные расходы и нулевые вертикальные), drawNetwork, plotNetwork
и создание окна run. Проверки прошли.
Полный интерактивный цикл и двухфазная динамика не проверялись; сохранены
существующие ограничения main. Исторические замеры analysis/ нельзя
автоматически переносить на текущую версию рабочих функций.
